# 🏛️ Нейминг и архитектура: pillars / amalgam

> **pillars — стойкость. amalgam — полигон.**
> Одно имя держит крышу, второе — место, где можно ломать.

---

## Два имени, две роли

| | **pillars** | **amalgam** |
|---|---|---|
| Роль | Стабильное ядро движка | Тестовый полигон / лаборатория |
| Что живёт | Проверенные SIMD-модели, типизированные `ComputeNeuron`, ядро `core/` | Эксперименты: VM-байткод, фармакология, калибровка, MuJoCo |
| Философия | Столпы держат крышу — здесь ничего не падает | Амальгама по определению пёстрая — здесь можно смешивать всё |
| Приём кода | Только после валидации | Свободный, черновой |
| Форма жизни | `crates/pillars` (Rust) | `amalgam/` — крейт `tnmt` (Rust + Python pyo3) |

Название **pillars** не случайно: архитектура движка держится на двух столпах —
**Event-Driven Push** (событийная рассылка спайков по CSR) и
**Thread-Local Accumulation** (локальное накопление токов с SIMD-редукцией).
Имя — это чертёж: оно прямо описывает конструкцию.

Название **amalgam** честно описывает своё содержимое: сплав нейробиологии,
фармакокинетики, физики и обучения в одном интерпретируемом байткоде.

---

## Правило продвижения (Graduation Rule)

Эксперимент живёт в amalgam до тех пор, пока не докажет, что достоин pillars.
Путь в ядро только один:

```
┌─────────────┐    парити-тест    ┌──────────────┐
│   amalgam   │ ─────────────────► │   pillars    │
│  (полигон)  │  spike-счёт +      │   (ядро)     │
│  можно всё  │  бенчмарк + clippy │  только чистое│
└─────────────┘  + доки           └──────────────┘
```

### Чеклист продвижения эксперимента в pillars

1. **Парити-тест** — spike-счёт и траектория V совпадают с эталоном (полигонная реализация или NEURON/Brian).
2. **Бенчмарк** — производительность не хуже существующего пути без веской причины.
3. **Качество** — clippy 0, типизированный API (никаких сырых индексов), доки.
4. **Честность** — известные ограничения документируются, а не прячутся (пример: LUT для HH помечен `#[ignore]` с причиной — 12-битный ключ не видит скрытые гейты m/h/n).

### Уже случившиеся продвижения

- **Triangulated LUT** — родился как эксперимент «таблица вместо ODE», продвинут в `zoo/neurons/triangulated.rs` с честными `#[ignore]` на известных пределах.
- **CaV-T канал** — добавлен в HHModel как 4-й гейт через `hh_channels::pacemaking_channels`, переведён из конфига `hh_pacemaking`.
- **ComputeNeuron-мост** — typed API (`#[derive(NeuronModel)]`) вытеснил сырые `ctx.s(0)`/`ctx.p(4)` по всему зоопарку.

## Мосты между полигоном и ядром

- **`taas_to_tnmt.py`** — читает бинарный TAAS1 (выход sardaanaCM) и конвертирует в формат tnmt (npz). Это канал «генератор → полигон».
- **`bench_tnmt_vs_taas.py`** — честное сравнение VM (интерпретатор) против SIMD-ядер (компилируемый путь). Оверхеред интерпретации — это цена гибкости, и она измеряется, а не предполагается.
- **HAAP-конфиги** (`haap_neuron_types.toml`) — иерархия параметров FAFB + MANC + C. elegans: `default < super_class < flow < class < sub_class < nt_type < neuropil < cell_type`. Калибруется в полигоне, продвигается в pillars как численные профили.

---

## Ограничения полигона (честно)

- **Интерпретатор медленнее компилируемого пути** — VM гонит байткод с диспетчеризацией, pillars компилирует модель в SIMD напрямую. Это не баг, это выбор: гибкость за такты.
- **16 регистров** — сложные модели (полный channelome) требуют ручного регистрового планирования в байткоде.
- **Column-major состояние** — безопасно при строгом контракте `num_states × n_neurons`; ошибки размера — UB (задокументировано в `vm_step_simd`).
